# 実験 B：弱いヘッドを切ると何が起きるか — 報告

**日付** 2026-09-25 ／ **対象** OpenIDH（IDH 変異予測、late fusion + evidential）
**再現** `scripts/head_ablation.py`（CSV 演算のみ）、`scripts/modality_drop_eval.py` + `qsub/modality_drop.sh`（推論のみ）
**数値** `results/head_ablation.json`、`results/modality_drop.json`、`runs/*/predictions_drop-*.csv`
**性質** 既存チェックポイントのみ。**再学習なし**。

発端は「ドメインシフトが起こりやすい状況では、最初から T2/FLAIR のヘッドを使わない（不明データとして扱う）方が良いのではないか」という提案。実験 A（`results/shift_decomposition_report.md`）で、vendor シフト時に T2/FLAIR だけが evidence を 2〜3 割失うと分かった直後の発想である。

## 1. 2 つの「切り方」を区別する

| | 操作 | 何を測るか | コスト |
|---|---|---|---|
| **head-off** | 融合の和から当該ヘッドの項を外す | 「そのヘッドの言うことを無視する」 | **0**（`predictions.csv` の列演算。融合は和なので厳密） |
| **true-missing** | 入力チャネルをゼロにしてから forward し、ヘッドも外す | 「そのシーケンスを撮っていない」 | 推論 1 回（訓練時の modality dropout p=0.2 と同じ経路） |

**両者は同じではない**：unified trunk は 4 シーケンス連結の 12ch 入力を受けるので、head-off では T2/FLAIR の情報が unified 経由で残る。提案の意図は true-missing の方であり、head-off はその**楽観側の上限**にあたる。

検算：true-missing の実装で「何も落とさない」pass を走らせると、既存の `predictions.csv` を **誤差 0.00e+00（728 症例）** で再現する。同じ推論経路であることの保証。head-off 側も、全ヘッドの和が保存済み α/β を再現することを assert してから使っている。

## 2. 結果（12 OOD ラン、ベースラインとのラン単位ペア比較）

| 構成 | ΔAUC | ΔECE | ΔNLL | AUC 改善 |
|---|---|---|---|---|
| head-off −T2,FLAIR | −0.003 | −0.019 | −0.011 | 4/12 |
| **true-missing −T2,FLAIR（提案の実体）** | **−0.020** | **−0.022** | **+0.015** | **1/12** |
| head-off −T1,T2,FLAIR | +0.013 | −0.021 | −0.022 | 8/12 |
| true-missing −T1,T2,FLAIR | −0.005 | −0.017 | +0.005 | 4/12 |
| （対照）−unified | −0.014 | 0.000 | +0.013 | 1/12 |
| （対照）−tabular | −0.007 | +0.002 | +0.012 | 0/12 |

**同じ落とし方どうしの比較（true-missing − head-off、12 OOD ラン）**：ΔAUC **−0.017、12 ラン中 11 ランで true-missing の方が悪い**（ΔNLL +0.026）。もう一方の落とし方でも −0.017（10/12）。

→ **unified は T2/FLAIR の欠損を肩代わりしない。** head-off の数字は予告どおり上限であり、提案どおりに「不明として扱う」と識別性能は約 0.02 下がる。

## 3. なぜ LOSO-B だけ較正が劇的に良くなるのか（実験 A との接続）

温度スケーリング（spec §10）は LOSO-B の較正を直せなかった：ECE 0.141→0.148、0.172→0.174、0.172→0.158（T = 0.95〜1.13、ほぼ 1）。**単調変換には切片が無い**からである。

ところがヘッドを切ると ECE 0.162 → 0.073 になる。理由は融合ロジットの平均移動を見ると明白：

| ユニット | 較正が要求する移動量 | all | head-off −T2,FLAIR | head-off −T1,T2,FLAIR | true-missing −T2,FLAIR |
|---|---|---|---|---|---|
| **LOSO-B** | **+1.09** | +0.33 | +0.52 | +0.56 | **+0.69** |
| LOSO-A | +0.25 | −0.21 | −0.11 | −0.09 | −0.29 |
| field | −0.05 | −0.33 | −0.36 | −0.34 | −0.34 |
| **vendor** | **+0.42** | +0.20 | **−0.07** | +0.04 | **−0.16** |

**ヘッドを切ることは、部分的な切片補正として働いている。** LOSO-B では要求 +1.09 に対し実測 +0.33 しかなかったものが、T2/FLAIR を外すと +0.52〜+0.69 まで回復する。

これは**実験 A が予測したとおり**である。実験 A では LOSO-B について「症例構成の成分が criterion を押し上げ（+0.13〜+0.42σ）、撮像の成分が T2/FLAIR/unified で押し下げる（−0.24〜−0.43σ）ので打ち消し合う」と分かっていた。**押し下げている側のヘッドを外せば、打ち消しが解ける。**

逆に vendor では実験 A の $d_p$ が T2/FLAIR とも **+0.35 と正**（criterion を押し上げる側）だった。だから外すとロジットは +0.20 → −0.07 と**要求（+0.42）から遠ざかり**、ECE は 0.085 → 0.106 と悪化する。実測はこの予測どおり。

→ **予測ルールが立つ**：外そうとしているヘッドの $d_p$ の符号が、そのシフトで必要な切片補正と**逆向きなら較正が改善し、同じ向きなら悪化する。** 実験 A の分解表があれば、切る前にどちらになるか分かる。

## 4. 結論

1. **提案（T2/FLAIR を不明として扱う）は、識別性能を上げない。** 12 OOD ランで AUC −0.020、改善したのは 1 ラン。head-off の −0.003 は上限であり、真の欠損版はそれより 0.017 悪い（11/12 ラン）。**unified は肩代わりしない。**
2. **較正は改善する（ECE −0.022、8/12）。ただし効果はほぼ LOSO-B に集中し、vendor では悪化する。** 「シフト全般に効く一手」ではなく、**シフトの向きに依存する**。
3. **温度スケーリングで直せなかった LOSO-B の較正が、ヘッド除去では直る。** 前者に切片が無く、後者が部分的な切片補正として働くため。ただしこれは「たまたま符号が合った切片補正」であり、原理的には切片を直接扱う方が筋が良い。
4. **分布内では、T2/FLAIR は撮っていないことにしてもほとんど損をしない**（AUC −0.004）。単独シーケンスヘッドが持つ固有情報は小さい。Phase 2 の case A/B ヘッド ablation を検討する材料になる。
5. 対照は健全：unified を外すと −0.014、tabular を外すと −0.007 と明確に悪化する（12 ラン中 11〜12 ランで悪化）。手法は実害を検出できている。
6. **inner-val で構成を選ぶことはできない。** val 最良の構成を test に適用してもベースラインとほぼ同点（例：LOSO-A で val 選択 0.856 に対し test 最良は 0.883）。採用するなら**事前の設計判断**として決める必要がある。装置ベンダー・磁場強度は推論時に既知のメタデータなので、運用ルール自体は検出器なしで書ける。

## 5. 限界

- 12 OOD ラン（4 ユニット × 3 seed）。ユニット内の seed 間ばらつきは AUC で 0.02〜0.06 あり、上の平均差（0.02 前後）と同オーダー。**「大きく下がる」とは言えるが、「0.017 下がる」の精度は保証しない**
- true-missing は rand0_s0 以外の分布内ランでは未実施（陰性対照は 1 ランのみ）
- 較正指標（ECE）は 10 ビン等幅。LOSO-B の test 619 例では 1 ビンあたり数十例で、±0.01 程度の揺れは想定内
- 切片の議論は**平均ロジットの移動**で見ている。ビンごとの形状は見ていない（実験 A の報告にある「LOSO-B のずれはビン間でほぼ定数」という既知の結果に依拠している）
- 再学習していないので、「最初からそのヘッドを作らない」設計の性能は測れていない（Phase 2 の課題）

## 6. 再現方法

```bash
# head-off（GPU 不要、数秒）
uv run python scripts/head_ablation.py --json results/head_ablation.json

# true-missing（チェックポイントのある計算機、推論のみ、約 15 分）
qsub qsub/modality_drop.sh
#   -> runs/<run>/predictions_drop-<tag>.csv
# 以後は head_ablation.py がそれらを自動で拾い、同じ表に並べる
```
